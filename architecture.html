Architecture of the working proof · 5 September 2026

Keep the harness.
Bound the local work.

Local Agent Optimizer lets Codex and Claude Code keep control of the user's work. A conservative router can send a small implementation packet to a local worker; the parent harness reviews and verifies the result.

01

What this repository is trying to prove

Local execution must earn its place through verified outcomes and acceptable resource use. The current proof establishes a narrow path; it does not establish net savings or broad coding quality.

Keep the user's workflow

Codex and Claude remain the planners, interfaces, and verifiers. LAO installs once and restores its managed client changes with lao off.

Spend trust carefully

Native credentials stay inside the gate. Local packets get exact file permissions and fresh state. Capture, cloud evaluation, spend, and training require explicit consent.

Stay small on the machine

One owned llama.cpp engine, a Light memory budget, bounded caches, and pressure eviction. Components communicate through APIs and own their private state.

02

Two entry points, one protected runtime

The MCP packet path and native HTTP overlay coexist. They have different decision boundaries and both matter when reading the code.

A. Delegated implementation packet

Harness → stdio MCP → lao mcp
Codex / Claude plannerOne objective + up to 16 exact repository-relative file paths.lao.execute
→
CLI + semantic routerapp/cli owns the MCP loop and composes svc/route. MiniLM judges the objective once.
→
Cloud → return controlThe current harness implements the work. No OpenCode worker starts.
Local → OpenCode → Qwen3Fresh state per call. Exact read/edit tool permissions. Model calls go through authenticated /wrk/v1/chat/completions on the daemon.

Return to the parent: outcome + changed allowed paths. The harness inspects the actual diff and verifies the task. No session continuation, automatic retry, or mid-loop cloud fallback.

B. Native model request overlay

Responses / Messages HTTP + SSE
Codex / Claude requestThe existing harness sends native model traffic through its configured LAO endpoint.
→
Gate + router in daemonAuthenticate first. Keep headers, credentials, and targets private. Expose only bounded current-user text to the router.
→
Cloud → native providerOriginal body passes through to the approved native origin.
Local → llama.cppAutomatic text routing rebuilds a tool-free body from final user text and lao-local. The explicit smoke canary has its own validated path.

Stream back through the gate: the runtime lease lasts until the response completes or is dropped. Native provider credentials never go to local inference.

Both paths use the same router implementation, instantiated in their own process. Worker model calls are already committed to Local and are not independent semantic-routing decisions. Unsupported automatic text requests and classifier failures stay Cloud.

03

What runs, and for how long

Process boundaries protect lifecycle and private data. Package boundaries protect ownership even when code shares a process.

User-invoked application

lao CLI

app/cli

  • install, preview, status, smoke, off.
  • Owns the install lock, recovery record, and before/after settings snapshots.
  • In MCP mode, lives with the harness and starts a worker for each Local packet.
Per-user launchd service

lao-daemon

app/daemon composes gate, router, runtime, model, and optimizer.

  • Adopts the loopback listener and owns caller authentication and streaming.
  • Loads MiniLM lazily; starts local inference only when a local path needs it.
  • Warms fixed Codex and Claude canaries in the background.
  • Retains bounded runtime caches; checks idle memory pressure every five seconds.
Supervised child processes

OpenCode + llama.cpp

OpenCode 1.18.25 executes a packet. llama.cpp 10280 serves Qwen3 4B Q4_K_M.

  • OpenCode gets disposable HOME/data/cache/state directories per turn.
  • The engine uses a 16K context, bounded threads, and a fresh fit check before cold load.
  • Model cache residency is separate from worker transcript state.

Install verifies and pins runtime/model artifacts and the OpenCode support tree. It checks launchd readiness before transactional client writes. off stops owned processes and restores LAO-owned settings while preserving unrelated client edits. External runtime endpoints remain user-owned.

05

What the boundary actually guarantees

Keep model quality, permission enforcement, and lifecycle cleanup separate. They provide different kinds of evidence.

SituationBehaviorImportant limit
Uncertain routingAutomatic classifier failure or unsupported request shape stays Cloud.Prototype similarity is a quality heuristic, not a security classifier or certified difficulty model.
Local file accessReject absolute paths, Git metadata, symlinks, wildcards, and backslashes; grant only named read/edit tools.Enforced by pinned OpenCode permissions, not an OS filesystem sandbox. Parent diff review remains necessary.
Worker stops after an editReturn bounded failure/timeout metadata and observed allowed-file changes when available.Edits may already exist. Inspect before retrying. A complete status is also not proof that the objective was met.
Next packet arrivesCreate fresh worker state; accept no session continuation handle.State is removed on normal return. Abrupt host termination is not a secure-erasure guarantee.
Memory pressureEvict an idle runtime; a later cold load repeats the fit check.Active response leases prevent eviction during a stream. This is a supported-Mac proof, not portable resource certification.
Client settings divergePreserve unrelated edits; reject conflicts in LAO-owned entries.Install/off manage only supported settings and versions, never harness credential stores.
06

Working proof, with a visible edge

Historical measurements belong to the configuration that produced them. Source checks protect contracts; they do not recreate installed-client results.

Evidence retained

  • Saved-login cloud/local/restart/off acceptance on the supported Mac.
  • Natural one-file delegation through Codex 0.151.0 and Claude Code 2.1.251; broad planning controls stayed Cloud.
  • Recorded delegated turns: about 35 seconds in Codex and 26 seconds in Claude; runtime RSS about 4.70 GiB under the 6 GiB Light ceiling.
  • Focused checks for independent packet state, partial-failure cleanup, rejected continuation arguments, exact file paths, and parent-death worker cleanup.
Open the dated acceptance ledger →

Not established by this proof

  • Net cost/quota savings, broad coding success, or production routing certification.
  • Astra gateway compatibility or future Codex/Claude version parity.
  • OS-level worker sandboxing, signed release packaging, or a full interactive/API-key compatibility matrix.
  • Certified vLLM/SGLang inference, cross-platform support, personal evaluation, or model training.

User-managed loopback adapters exist. Their presence is an API seam, not an integration certificate.
