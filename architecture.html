2. Trust boundaries

Caller

Each harness has a separate owner-only capability. launchd owns the loopback listener before settings change.

Decision

The gate keeps the request and secrets. The router sees only client, operation, and the canary fact.

Egress

Local receives no provider credential. Cloud can reach only the matching native origin over verified TLS.

client requestcaller token + native auth
→

Only the exact, non-secret canary selector permits Local. Every normal request remains Cloud. The implementation plan carries the detailed protocol and acceptance evidence.

Why a monorepo?

Contracts and consumers can change atomically while the project is young. Package boundaries—not repository boundaries—enforce ownership. A component can move out later without changing its API.

What is a component?

Usually one api/x package plus one svc/x package. An app selects implementations and gives them a process.

What is private?

State, migrations and sensitive internal stages. Credentials remain inside svc/gate. Raw captured content remains inside svc/capture.

7. The architecture is executable

cargo xtask check

Rejects forbidden imports, cycles, state collisions, hidden paths and policy mistakes.

cargo test --workspace

Builds every package and runs boundary and linked/RPC conformance tests.

cargo xtask extract

Builds a fake component outside the repo using only public seams.
